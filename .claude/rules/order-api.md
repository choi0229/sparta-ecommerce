# order-api 작업 규칙

`order-api`는 주문 생성, 주문 상태 관리, 주문 스냅샷 저장, Saga 오케스트레이션, 멱등성 처리를 담당합니다.

## 핵심 원칙

- `order-api`는 주문 상태와 주문 이력을 소유합니다.
- 상품, 재고, 결제 도메인의 원천 데이터는 소유하지 않습니다.
- 다른 서비스의 DB에 직접 접근하지 않습니다.
- 서비스 간 통신은 API 또는 Kafka 이벤트를 사용합니다.
- 비동기 주문 흐름을 blocking 흐름으로 되돌리지 않습니다.

---

## 주문 생성 / 스냅샷 규칙

주문 생성 흐름에서는 `Idempotency-Key`를 확인하고, 중복 요청이 중복 주문으로 이어지지 않도록 합니다.

주문 항목에는 주문 시점의 상품 정보를 스냅샷으로 저장합니다.

스냅샷에는 다음 정보를 고려합니다.

- 상품명
- 상품 가격
- 상품 옵션
- SKU / Variant
- 주문 수량
- 주문 금액 계산에 필요한 값

상품명, 가격, 옵션, SKU 정보가 이후 변경되더라도 기존 주문 이력은 변하지 않아야 합니다.

주문 스냅샷을 현재 상품 데이터에 대한 실시간 참조로 대체하지 않습니다.

---

## 트랜잭션 경계 규칙

`@Transactional` 내부에서 오래 걸리는 외부 호출을 수행하지 않습니다.

특히 다음 작업은 DB 트랜잭션 내부에서 수행하지 않습니다.

- Kafka request-reply 대기
- 상품/재고/결제 서비스 동기 호출
- Elasticsearch 호출
- 장시간 blocking 작업

외부 호출과 DB 저장이 모두 필요한 경우 다음 구조를 우선합니다.

- `OrderService`: 외부 호출, 흐름 제어, 요청 검증
- `OrderTransactionalService`: 짧은 DB 트랜잭션 안에서 주문 저장, outbox 저장

주문 생성 과정에서 외부 응답 대기 때문에 DB 커넥션을 오래 점유하는 구조를 다시 도입하지 않습니다.

---

## 비동기 주문 처리 규칙

주문 생성은 가능한 경우 비동기 흐름을 유지합니다.

기대 흐름은 다음과 같습니다.

```text
주문 요청
→ 요청 접수 응답
→ 주문 초기 상태 또는 요청 저장
→ Outbox 이벤트 저장
→ Kafka 이벤트 발행
→ Consumer 처리
→ 재고 예약
→ 결제 처리 또는 결제 이벤트 대기
→ Saga 상태 갱신
→ 상태 조회 API로 결과 확인
```

인메모리 pending state로 주문 상태를 관리하지 않습니다.

여러 인스턴스 환경에서도 상태가 유지되도록 durable storage를 우선합니다.

---

## Outbox / Saga / 멱등성 규칙

주문 상태 변경과 이벤트 발행이 함께 필요한 경우 Transactional Outbox 패턴을 유지합니다.

- 주문 저장과 outbox 저장은 같은 트랜잭션에서 처리합니다.
- Kafka 이벤트는 DB 커밋 이후 outbox 기반으로 발행합니다.
- DB 커밋 전에 Kafka 이벤트를 직접 발행하지 않습니다.
- 이벤트 발행 실패 시 재시도 가능해야 합니다.
- 구현 단순화를 이유로 outbox 로직을 제거하지 않습니다.

Saga 상태는 명시적으로 추적되어야 합니다.

- 주문 생성, 재고 예약, 결제 처리, 보상 처리 단계의 성공/실패 상태를 구분합니다.
- 실패 상황에서 주문 상태가 성공으로 남지 않아야 합니다.
- 재고 예약 실패, 결제 실패, 결제 timeout 시 기존 정책에 따라 보상 처리를 수행합니다.
- 보상 처리는 중복 실행되어도 안전해야 합니다.

Kafka 이벤트는 중복 전달될 수 있으므로 Consumer와 보상 처리 로직은 멱등하게 동작해야 합니다.

중복 처리는 다음 기준을 고려합니다.

- `Idempotency-Key`
- eventId
- processed event record
- orderId
- sagaId

중복 요청이나 중복 이벤트가 중복 주문, 중복 결제, 중복 보상으로 이어지지 않도록 합니다.

## 테스트 규칙

`order-api`의 비즈니스 로직을 수정한 경우 다음 테스트를 고려합니다.

- 정상 주문 생성
- 중복 주문 요청
- 중복 Kafka 이벤트 수신
- 상품 스냅샷 저장
- 재고 예약 실패
- 결제 실패
- Saga 보상 처리
- 트랜잭션 경계 분리
- Outbox 저장 및 발행 대상 생성

테스트는 가능한 경우 다음 명령어로 실행합니다.

```bash
cd order-api
./gradlew test
```

테스트를 실행하지 못했다면, 실행하지 못한 이유와 사용자가 실행해야 할 명령어를 명확히 설명합니다.
